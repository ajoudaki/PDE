# Software and Neural Tangents audit

Date: 2026-10-11. Scope: the assigned MFP manuscript/code, primary Neural Tangents paper and software, Thomas Ahle's Tensorgrad, and selected GP4A implementations. No other studies, earlier verdicts, book files, manuscript edits, or Git mutations were used. The canonical-notation skill, its neural-network reference, and `solve-math-rigorously` were read and applied.

## Finding

The inspected sources do **not** expose the same complete transformation as MFP: an admitted finite neural derivative/update program is automatically converted to a Gaussian source-response graph of dimension independent of width, with the manuscript's stated fixed-program limit theorem attached to that transformation. This is a defensible **interface and integration distinction within this shortlist**, conditional on the MFP theorem being correct. It is not evidence of a new general probabilistic program theorem, nor an exhaustive priority claim.

The component-level overlap is substantial. Neural Tangents already supplies arbitrary-order finite-network Taylor expansions and automatic infinite NNGP/NTK kernels. Tensorgrad already supplies symbolic higher derivatives, symbolic Gaussian means/covariances, tensor Stein/Wick reduction, shared/transposed matrix algebra, and unevaluated expectation nodes. An executed Tensorgrad composition also reproduces MFP's scalar moving-flow example. Therefore “first symbolic Gaussian calculus,” “first higher derivative compiler,” “first moving-flow differentiation,” “first arbitrary-geometry calculation,” or “first automatic infinite neural network” would be unsupported claims. [Neural Tangents paper, §§1.4, 3, B.2–B.7](https://arxiv.org/pdf/1912.02803v1), [Tensorgrad expectation implementation](https://github.com/thomasahle/tensorgrad/blob/59c85e4b34bc7f217383e9116d445c60e1b69ccf/tensorgrad/extras/expectation.py), [Tensorgrad derivative rules](https://github.com/thomasahle/tensorgrad/blob/59c85e4b34bc7f217383e9116d445c60e1b69ccf/tensorgrad/grad.py).

“Numerical kernel” here describes the returned object, not an assertion that every kernel formula is approximate. Many Neural Tangents layer formulas are analytic and are then evaluated with floating-point arrays. Conversely, returning an exact unevaluated integral does not mean MFP has numerically solved it.

The frontend distinction about covariance is material. `Program.roots` accepts concrete numeric covariance entries and checks positive semidefiniteness. Symbolic geometry enters through explicit factors, for example `alpha*U` and `beta*U+gamma*V`, giving `G11=alpha**2`, `G12=alpha*beta`, `G22=beta**2+gamma**2`. MFP's lower-level Gaussian expression reducer can accept symbolic covariance entries, with PSD a caller obligation; that is not a frontend accepting an arbitrary symbolic covariance family and inferring its neural realization. Tensorgrad's `Expectation` directly accepts a symbolic covariance tensor, but the user supplies its distributional interpretation. See MFP `main.tex:1838`, `main.tex:2065`, `mfp_compiler.py:205`, and `mfp_expr.py:340`.

## Neural Tangents: strongest overlap and exact boundary

The 2019 paper is a genuine automatic finite-to-infinite architectural translation system, not merely a collection of user-entered kernel formulas. Its contributions include automatic batching/distribution, empirical kernels, kernel prediction, and finite Taylor models. Appendix B.6 explicitly permits arbitrary Taylor order; Figure 6 trains a quadratic approximation. Appendix B.7 asks a new-layer author to provide the corresponding kernel transform. These points rule out framing MFP against a first-order-only or wholly manual baseline. [Complete primary paper](https://arxiv.org/pdf/1912.02803v1).

The exact finite expansion is visible in [`_src/empirical.py:193–237`](https://github.com/google/neural-tangents/blob/c17e770bb74f1771da7be4a69fabfa68b6078960/neural_tangents/_src/empirical.py#L193): `taylor_expand(f, params, degree)` recursively applies JVPs in the fixed displacement `new_params-params`. It returns an executable function, not a width-independent Gaussian expectation expression. This fixed-displacement API is not itself the Lie-derivative construction for a state-dependent training field, but arbitrary JAX differentiation can implement that construction. It would be incorrect to claim the underlying system cannot take moving derivatives.

The present infinite activation interface is broader than Appendix D's 2019 list. [`Elementwise`, lines 1024–1129](https://github.com/google/neural-tangents/blob/c17e770bb74f1771da7be4a69fabfa68b6078960/neural_tangents/_src/stax/elementwise.py#L1024) accepts the bivariate Gaussian moment function and can differentiate it with respect to covariance to obtain the derivative-activation moment. [`ElementwiseNumerical`, lines 1134–1230](https://github.com/google/neural-tangents/blob/c17e770bb74f1771da7be4a69fabfa68b6078960/neural_tangents/_src/stax/elementwise.py#L1134) constructs a Gauss–Hermite rule; its documented time/memory cost for the two-dimensional rule is quadratic in quadrature degree. Thus “Neural Tangents only handles closed-form activations” is outdated.

Likewise, a universal “no sharing” statement is false. The paper's §3 qualifies its compositional discussion by absence of inter-layer tying, but current [`GlobalSelfAttention`](https://github.com/google/neural-tangents/blob/c17e770bb74f1771da7be4a69fabfa68b6078960/neural_tangents/_src/stax/linear.py#L1985) has a specific analytically tractable tied-key/query case. Repeating a `stax` layer, however, is not arbitrary parameter reuse: [`repeat`](https://github.com/google/neural-tangents/blob/c17e770bb74f1771da7be4a69fabfa68b6078960/neural_tangents/_src/stax/combinators.py#L74) splits initialization keys and stacks separate parameter draws. None of these inspected interfaces supplies MFP's generic rule for all earlier calls to a named matrix in both orientations.

Its practical advantages are substantial: broad CNN/pooling/attention-related layer support; reusable numerical kernels on real batches; JAX/XLA acceleration; batching; prediction solvers; and finite empirical kernels for much broader finite code. MFP does not replace that functionality. [`predict.gradient_descent_mse`](https://github.com/google/neural-tangents/blob/c17e770bb74f1771da7be4a69fabfa68b6078960/neural_tangents/_src/predict.py#L71) solves the fixed-kernel function-space dynamics; [`gradient_descent`](https://github.com/google/neural-tangents/blob/c17e770bb74f1771da7be4a69fabfa68b6078960/neural_tangents/_src/predict.py#L317) integrates the corresponding ODE for general loss.

MFP's moving feature-kernel example uses readout normalization `1/n`, vector mobility `n`, and a particular half-mean-square-loss clock. A nonzero second feature-kernel jet in that model does not contradict the fixed-NTK limit in Neural Tangents' parameterization. The observable is also the last-layer feature kernel/readout block, not the full tangent kernel. These normalization and observable differences must accompany any side-by-side result.

## Tensorgrad: a material symbolic competitor

The defining code is [`Expectation`](https://github.com/thomasahle/tensorgrad/blob/59c85e4b34bc7f217383e9116d445c60e1b69ccf/tensorgrad/extras/expectation.py#L18). The constructor takes a tensor expression, Gaussian variable, symbolic mean and covariance, and edge correspondence. `_simplify_product` (lines 196–253) removes one occurrence of the Gaussian variable and contracts its covariance with the expectation of the remaining derivative: this is tensor Gaussian integration by parts, not numerical sampling. `_simplify_function` retains unknown expectation nodes. The source specifically mentions transposed occurrences. The upstream [`test_quartic`/`test_quartic2`](https://github.com/thomasahle/tensorgrad/blob/59c85e4b34bc7f217383e9116d445c60e1b69ccf/tests/extras/test_expectation.py#L88) exercise repeated Gaussian matrices, transposes and deterministic matrix factors. Those upstream tests were inspected, not executed here.

Its named symbolic dimensions, higher-rank tensors, arbitrary contractions, user-defined function signatures, and symbolic covariance inputs cover operations beyond MFP's finite typed language. Its symbolic derivative graph can be evaluated or compiled separately. Conversely, the inspected expectation engine is not a general analytic integration oracle: non-polynomial functions often remain `Expectation` nodes, and `full_simplify` iterates rewrites to a fixed point without a stated universal complexity guarantee. `Expectation._grad` differentiates the integrand while retaining the supplied law; no general law-parameter differentiation contract was verified. This latter limitation is not needed to distinguish it from MFP, whose physical derivatives likewise do not implicitly differentiate a sampling law.

There is a precise semantic difference between two unevaluated integrals. A Tensorgrad expectation over all entries of an `n x n` Gaussian matrix can still be an integral over a space growing with `n`. MFP's compiler eliminates width, replacing each fixed program's matrix calls by a finite set of Gaussian coordinates and response coefficients. Merely putting an `Expectation` wrapper around the original finite neural expression does not perform that reduction or establish scalar concentration. On polynomial examples, symbolic Wick contraction followed by a user-derived large-`n` limit is a plausible alternative route; this audit does not assert that such a route is impossible or unique to MFP. Tensorgrad could also serve as a symbolic backend for already-derived limit equations.

A direct executed overlap check uses a scalar evolving state `x`, observable `O(x)=x^2`, and vector field `V(x)=-x^3`. Define `D_V F=F'(x)V(x)`. Then

\[
D_VO=-2x^4,\qquad D_V^2O=8x^6,
\qquad \mathbb E[D_V^2O(X)]=120,\quad X\sim N(0,1).
\]

The installed-source calculation `Expectation((O.grad(x)*V).grad(x)*V, x).full_simplify()` returned exactly `120`. Thus the moving term `DO[DV[V]]` can already be represented and evaluated with symbolic differentiation plus Gaussian expectation. MFP's contribution, if established, is not this elementary mechanism; it is closure and automatic limit evaluation for its admitted neural programs.

## GP4A: relevant implemented theory, not a universal compiler

The [primary README](https://github.com/thegregyang/GP4A/blob/23e4bc76fafc0a17c187562862d065fa18ed7b9e/README.md) explicitly limits the repository to selected architectures. [`RNNtheory.py:3`](https://github.com/thegregyang/GP4A/blob/23e4bc76fafc0a17c187562862d065fa18ed7b9e/RNNtheory.py#L3) accepts a normalized input Gram, sequence indexing and an activation transform, then returns a numerical GP kernel. This is meaningful support for recurrent weight reuse and arbitrary compatible Gram inputs. [`GRUtheory.py:110`](https://github.com/thegregyang/GP4A/blob/23e4bc76fafc0a17c187562862d065fa18ed7b9e/GRUtheory.py#L110) returns lazily memoized covariance and expectation functions; its erf-derived gates use the R `mvtnorm` package for Gaussian orthant probabilities.

The Transformer notebook's kernel routine and the Batchnorm notebook's integrands/quadrature show substantial architecture-specific analytic work followed by numerical evaluation. Their value is precisely that they turn nontrivial theory into working kernel recipes. Neither the README nor inspected source presents an arbitrary typed derivative-program compiler, a general shared-transpose source-response pass, or symbolic moving-kernel jets with free labels. The separate NTK4A repository was **screened only through GP4A's link**; it was not inspected and no absence claim about it is made here.

## Positioning consequence

A supportable software positioning is: **MFP integrates exact differentiation of a restricted finite Gaussian neural-program language with automatic source-response evaluation of its fixed-width-limit observables, retaining explicit generic-activation integrals, shared matrix identities and moving derivative requests.** It should acknowledge that finite symbolic AD, Gaussian expectation reduction, architectural infinite-kernel compilation and recurrence-aware theory already exist. The convincing application is a nontrivial admitted neural derivative/update calculation that crosses those components automatically, with clear normalization and independent verification—not the mere coexistence of derivative and expectation symbols.

No software evidence here establishes an efficiency advantage. MFP itself disclaims efficient high-order compilation and positive-time reconstruction; retained Gaussian integrals may be difficult to evaluate. Neural Tangents has stronger numerical engineering and broader supported layer families; Tensorgrad has broader tensor algebra and directly symbolic covariance inputs; GP4A demonstrates specialized recurrent and normalization recipes outside MFP's simple smooth primitive frontend. The distinctions should be stated as different scopes and outputs, not a universal hierarchy.
