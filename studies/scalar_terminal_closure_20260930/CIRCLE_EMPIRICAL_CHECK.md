## Independent computation

Initial A and W0 were regenerated in the declared draw order with NumPy default_rng seed 20260920. They matched the saved initialization exactly, and the stored initial readout was exactly zero. Run initialization hashes agreed with this shared source. Input labels, stored training angles, query-grid construction, frozen-source hashes, and numeric saved-array finiteness were checked. Each audited file was hashed before and after reading to guard against a concurrent partial write.

For q=1, the checker explicitly forms `B = W0 + values @ keys.T/(m*n)` and uses B and its actual transpose for forward and backward evaluations. It does not call the producer's factored-mixer fields or response routine. Tanh gates are differentiated as `1-tanh(z)^2`, independently of the producer's exponential gate formula. Training and query C,b entries are reconstructed by per-example contractions. A separate direct microscopic velocity calculation, including Bdot from value and key motion, checks `fdot=-C r+||r||b` at each unseen query.

Fourier coefficients at primary handoffs are regenerated by explicit sine/cosine sums over all 2048 sampling points, rather than the producer's FFT. Scalar query readouts are reconstructed from the saved integrated residual and integrated norm; at all saved times the checker also verifies `r=r0-C I+b J` and recomputes loss from r. This checks observer/integral consistency, not an independent scalar ODE integration.

## Finiteness, memory, and coverage limits

All numeric arrays in the audited initialization, endpoint, handoff, and curve NPZ files were finite. Source inspection shows that the producer checks `dense_loss + q1_loss` for finiteness and checks the loss magnitude at each main training iteration. It does **not** independently test or log every state coordinate or every intermediate RK4 stage for finiteness. This audit therefore establishes finite saved states and records the producer's per-step loss checks; it does not establish strict coordinatewise full-step/stage finiteness throughout training.

The reported producer `peak_rss_bytes` is a maximum of sampled `psutil.Process().memory_info().rss` values at main-loop checkpoints. It is not continuous high-water memory accounting, and can miss temporary allocations inside RK4, capture, Fourier work, or postprocessing. The inspected producer does not enforce the plan's 4 GiB limit by a process memory limit or an abort-on-RSS test. Neither that reported sample maximum nor this checker certifies a strict memory peak below 4 GiB.

The audit does not independently reproduce training steps, verify all common-time loss values against microscopic states, certify interpolation between saved observations, prove numerical convergence, prove terminal-tube hypotheses, or establish whole-circle/infinite-time accuracy. Coarse/fine fidelity and campaign decision metrics remain the root's full-data analysis responsibility. No population or asymptotic state-cost claim follows.
