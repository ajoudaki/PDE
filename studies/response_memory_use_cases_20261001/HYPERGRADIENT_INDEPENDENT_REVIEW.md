The reviewed object is a two-hidden-layer, bias-free tanh network with width (n), eight training inputs (u_a=(\cos\theta_a,\sin\theta_a)), and output (f_a=w^\top h_a^{(2)}/n), where (h_a^{(1)}=\tanh(W^{(1)}u_a)) and (h_a^{(2)}=\tanh(W^{(2)}h_a^{(1)})). The inputs already contain the paper's input normalization. The loss is the unhalved mean squared error, with residual (r_a=f_a-y_a), mobilities ((n,1,n)), Gaussian hidden initialization, and exactly zero initial readout. Labels alone are optimized, with fixed initial weights shared by each design/retraining pair. The inner computation is 256 simultaneous Euler steps to physical time (T=8), followed by 24 Adam label updates of size 0.05 and projection to ([-3,3]^8). This review checks derivatives of that finite computation; it does not infer derivatives of continuous-time or infinite-width limits.

**Limits and corrections.** These do not invalidate the narrow reproduced result, but they bound its interpretation.

1. **Held-out qualification.** The evaluation grid is excluded from outer gradients, but the pilot pass criteria use its MSE to choose q and the confirmation reuses that grid. Fresh confirmation seeds test sensitivity to initialization, not an untouched task or independently sampled evaluation domain. The report's precise statement “no test-based choice of outer iterate” is supported. The protocol's broader parenthetical “no test selection” should be read or rewritten with that qualification. The packet records the intended prospective protocol and amendments, but provides no independently timestamped immutable pre-run protocol/selection freeze; this review verifies the recorded design and executed outcomes, not external preregistration chronology.

2. **Mechanism remains partly unresolved.** Defeating the two specified frozen objectives supports utility of this feature-aware surrogate. It does not isolate learned middle-layer response memory as necessary: gain/time-calibrated frozen dynamics, a moving first layer with fixed middle matrix, generic low-rank dynamics, and other feature-learning inner surrogates were not tested in this packet. In particular, making the uncalibrated frozen objective's optimization more accurate can worsen transfer without rejecting every frozen-feature explanation. Keep “disfavored” attached to the tested controls, not all initialized-kernel alternatives. I did not inspect later controls.

3. **The theorem does not cover this experiment as stated.** Besides the unverified small-label threshold, antipodal training inputs and odd activations make opposite feature columns exact negatives, so the full eight-sample readout Gram has rank at most four and cannot satisfy the manuscript's strictly positive full-sample Gram gap. The four-dimensional antisymmetric restriction could be analyzed separately; no such extension is proved here. The report already disclaims a theorem for optimized unit-scale labels, and should explicitly mention this second hypothesis failure.

4. **Storage count terminology.** The CUDA peak figures and their arithmetic are consistent, and the report correctly uses matched checkpointing rather than claiming a speedup. The dense table's “fixed matrix scalars = 0” is a theoretical count of extra coefficients required by the dense RHS. The actual `FunctionalFlow` object retains `self.W0` even for dense training, while its evolving state allocates subsequent matrices. Thus literal resident initialization storage is nonzero for dense too. Label that column as an additional mathematical coefficient requirement, or disclose the dense initializer retention. Measured peaks already include it, so the reported allocation comparison is unaffected.

5. **Performance and numerical scope.** The warm CUDA benchmark is one synchronized gradient per method/width/strategy. I audited its code and both raw benchmark versions, and reproduced checkpoint-gradient parity on CPU, but did not independently rerun CUDA allocation or timing. The 61.16% allocated-peak reduction and 61.25% extra runtime are implementation-specific observations with the report's stated exclusions, not hardware-wide confidence intervals or optimal recomputation comparisons. Half-step replay establishes stability of the reported fixed designs; it does not show convergence of reoptimized labels, optimized hypergradients, q-order derivatives, or infinite-time dynamics.

6. **Reproduction conveniences and provenance.** `--mode run --device cpu` still calls CUDA memory/synchronization APIs unconditionally, so CPU reproduction needs the supplied review loop or a device guard. This does not affect the original explicitly CUDA runs. The raw labels and conditioning are preserved, but `hypergradient_summarize.py` does not itself generate `optimized_labels.csv` or `frozen_conditioning_cpu.json`; the claim that summaries reproduce with that single command should specify which products it creates. The conservative 1095-inner-solve total is hard-coded in the summary script rather than derived from an invocation ledger; I verified the 864 main optimization solves but did not independently certify every accounting convention or the console-only preflight. These are minor reproducibility/reporting limitations.
