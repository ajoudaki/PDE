# Independent scientific review assignment

Review the frozen candidate identified by the packet’s `inputs.json` manifest.
The task is an adversarial mathematical and implementation review, not editing
or independent research to obtain a desired verdict. Do not assume correctness.

Read the complete supplied candidate, full proof/dependency bodies, custom code,
tests, and reproduction recipes. The manifest distinguishes proposed additions
from established dependencies and guides. Repair truncated reads. Standard
third-party software packages (including the bundled unmodified D3 library)
are software dependencies, not newly authored scientific claims; inspect the
custom viewer code and exercise its semantics. Record exact read coverage and
any unread material. Missing necessary inputs block a complete verdict.

Read the supplied project instructions/workflow and required skills. Use
`solve-math-rigorously` and `explain-with-canonical-notation` (including its neural
reference); use `investigate-conjectures` for scope/claim-level analysis as
needed. No author startup, study README/history, prior verdicts, other studies,
live manuscript, conversations or other review reports are allowed inputs.
Report a missing input rather than silently fetching project research.

Check every nontrivial proof step, assumptions, constants, dependencies,
probability quantifiers, limit orders, model normalization, state topology,
initialization and information available to the construction. Do not equate
fitting with predictor accuracy, a finite-panel estimate with a sphere bound,
an existence construction with the practical numerical initializer, or fixed
closure dynamics with the dense reference. Check scopes of local-minimum,
trainability, protected-flow and passive-prediction statements separately.

Audit all applicable implementation and test bodies. Run meaningful deterministic
checks and boundary attacks in your own supplied scratch directory, using only
the frozen edition. Check producers, numerical normalization, actual transpose
reuse, source provenance, roundoff/rank handling, interfaces, sampled versus
continuum errors and dataset separation. No research campaign or network dataset
download is authorized. Operational recipes make no empirical learning claim.

Write only your assigned report and scratch. Give component-level verdicts and
concrete objections with exact locations, severity, consequences and evidence.
Required corrections block acceptance. Include input hashes, actual commands
and results, complete read coverage, isolation/identity declaration, and an
explicit completion statement. Preserve adverse findings; do not silently fix
the candidate. A partial review is not a PASS. Report promptly if a substantive
blocker makes further downstream review wasteful, while retaining what has
actually been checked.
